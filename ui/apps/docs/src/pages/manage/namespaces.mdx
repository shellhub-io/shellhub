# Namespaces

A namespace is the boundary everything lives inside: devices, members, identities, policies,
tags, settings. Two namespaces share nothing.

<Shot id="namespace-settings" route="/settings" alt="Namespace Settings page" />

## Name and Tenant ID

Every namespace has both, and they do different jobs.

The **name** is human-facing and can be changed. It must be a valid hostname — lowercase, no dots
— because it appears in an SSHID:

```bash
$ ssh root@mycompany.raspberrypi@cloud.shellhub.io
#          ^^^^^^^^^ the namespace name
```

The **Tenant ID** is an immutable UUID generated when the namespace is created. It is what devices,
API keys and sessions actually reference.

<Shot id="tenant-id" route="/settings" of={{ role: "group", name: "Tenant ID" }} alt="The Tenant ID setting, with the control that copies it" />

Renaming a namespace changes every SSHID for it. Anything with a stored SSHID — an SSH config
alias, an Ansible inventory, a script — breaks. The tenant ID does not change, so agent
configuration is unaffected.

## Creating one

<Shot id="namespace-create" route="/devices" of={{ role: "dialog" }} edition="enterprise" before={[{ click: { testId: "namespace-selector" } }, { click: { text: "Create namespace" } }]} alt="The Create a Namespace dialog, asking for a name" />

<EditionBanner>
Creating a namespace is on **Cloud** and **Enterprise**. Community is single-namespace: the one
namespace is created at setup and the server refuses to create another. The route is not
registered, so an attempt returns 404 rather than an error explaining itself.
</EditionBanner>

Reasons to have more than one: separating customers, separating environments where the separation
must be absolute, or separating teams that should not see each other's devices. Within a single
namespace, [tags](/manage/devices/tags) and
[access policies](/manage/access-control/access-policies) handle most separation without the
overhead of a second workspace.

## Switching

<Shot id="namespace-switch" route="/devices" before={[{ click: { testId: "namespace-selector" } }]} alt="The namespace selector open, listing the namespaces this account belongs to" />

Membership is per namespace, and so is your role — you can be an administrator in one and an
observer in another.

## The SSH access mode

A namespace carries its access mode, which decides how connections are authorized. Namespaces
created today are born in identity mode. Namespaces predating it default to legacy and can be
switched.

A namespace born in identity mode can never leave it. See
[How Authorization Works](/manage/access-control).

## Deleting

<Shot id="namespace-delete" route="/settings" of={{ role: "dialog" }} before={[{ click: { role: "button", name: "Delete" } }]} alt="The Delete Namespace dialog, which asks for the namespace name before it will proceed" />

Deleting takes the devices, identities, policies and history with it. Only the owner can do it —
an administrator cannot.

Agents keep running on the devices. They no longer have a namespace to enroll into, so stop them
if the machines are staying in service.

## Device limits

Self-hosted Community has no limit. The Cloud free plan is limited to 3 devices.
