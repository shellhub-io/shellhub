# Accepting Devices

A device that enrolls with nothing but a tenant ID lands in **Pending** and waits for a human.

![ShellHub Devices page on the Pending tab where new devices await acceptance](/img/devices/device-pending.gif)

Accept it and it joins the namespace. Reject it and it does not.

## Why the pending list exists

A tenant ID is not a secret in any meaningful sense — it is visible in the console, it goes into
install commands, it ends up in scripts. Anything that learns it can enroll a device.

The pending list is the check on that. Enrollment gets a device *into the queue*; a member decides
whether it gets into the namespace.

## When it stops working

For one device this is fine. For fifty it is a bad afternoon, and for devices coming off a
production line it is impossible — nobody is watching a console when a unit at a customer site
powers on for the first time.

That is what [install keys](/manage/devices/install-keys) are for. A key in `automatic` mode
accepts devices as they enroll, and applies tags at the same time, so the fleet arrives already
sorted.

The pending list does not go away; it stops being the only path.

## Deciding what to accept

The pending entry shows what the agent reported: hostname, OS, architecture, agent version, and
when it appeared.

If something is there you do not recognize, that information is what you have. A hostname you did
not choose and an OS that does not match your fleet is worth investigating before accepting —
and rejecting costs nothing, since a legitimate device can be re-enrolled.

## Rejecting and removing

**Rejected** refuses the device but keeps the record, so you can see it was refused.

**Removed** deletes it from the namespace.

Neither stops the agent. If it is still running and configured, it will enroll again. To retire a
device, stop its agent first.

## Ephemeral devices

An install key can mark the devices it enrolls as ephemeral, for machines that are genuinely
temporary — CI runners, short-lived instances — so they do not accumulate in the list forever.
