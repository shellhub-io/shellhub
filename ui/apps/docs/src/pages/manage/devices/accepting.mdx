# Accepting Devices

Registering does not put a device in the namespace. Something still has to decide, and what
decides is the install key the device registered with.

## The key decides

An install key carries a mode, and the mode is the decision:

| Mode | What it does |
|---|---|
| Automatic | Accepts every device that registers with the key |
| Manual | Leaves the device pending, for you to review |
| Webhook | Asks your endpoint, at registration, to accept, reject or leave it pending |
| MAC allowlist | Accepts a device whose MAC is on the list, and rejects the rest |

A device that registers with only a tenant ID and no key is not an exception to this: it falls to
the namespace's **default key**, and that key's mode decides what happens to it. Disable the
default key and those registrations stop being accepted at all — the server refuses them outright
rather than parking them.

This is the part worth setting up before a fleet arrives. A key in automatic mode also applies its
tags as devices register, so they turn up already sorted; one in manual mode is a decision per
device, which is fine for one and a bad afternoon for fifty.

## Where a decision waits

A device left pending waits in the activity of the key it registered with.

Each entry carries what the agent reported — MAC address, source IP, architecture, agent version
— whether this is a new registration or the same device registering again, and the accept or
reject itself.

Accepting from a device's own page does the same thing, and is how you decide on one you arrived
at from somewhere else.

## Deciding what to accept

What you have is what the agent said about itself. A hostname you did not choose, or an
architecture that does not match anything you deploy, is worth understanding before accepting.

Rejecting costs little: a device that should be there can register again.

## Rejecting and removing

**Rejected** refuses the device and keeps the record, so the refusal is visible later.

**Removed** deletes it from the namespace.

Neither stops the agent. If it is still running and configured, it registers again. To retire a
device, stop its agent first.

## Ephemeral devices

An install key can mark what it enrolls as ephemeral, for machines that are genuinely temporary —
CI runners, short-lived instances — so they do not accumulate.
