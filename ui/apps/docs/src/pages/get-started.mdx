# Quickstart

<Callout variant="info">
This covers **ShellHub Cloud**, the hosted version. To run it on your own infrastructure, stand a
server up with the [Self-Hosting Quickstart](/selfhosted/quickstart) first and then come back.
From the account onwards everything here is the same, at your own address.
</Callout>

By the end of this page you will have a device you can open a shell on from anywhere, in the
browser or in your own SSH client. Nothing on the device listens for inbound connections.

## Create your account

1. [Sign up](https://cloud.shellhub.io/sign-up) with a name, a username, an email and a password,
   and accept the privacy policy.
2. Click the link in the confirmation email. Until you do, signing in returns you to the
   confirmation screen, which can send the email again.
3. Sign in.

The console opens on **Get your first shell**, a page that takes you through the rest of this
guide one step at a time: your namespace, the agent, the pairing and the first shell. On Cloud it
first asks a few questions about you. Leave it before pairing and it picks up where you stopped.

A namespace is what devices join. Its name is part of every address you use to reach a device, so
keep it short: 3 to 30 characters, lowercase letters, numbers and hyphens.

## Connect your device

A device is any machine running the agent. The agent opens one outbound connection to the server
and keeps it, which is what lets you reach the device through a NAT you do not control.

### Install the agent

The **Install the agent** step shows the command. Run it on the machine you want to reach:

```bash
$ curl -sSf https://cloud.shellhub.io/install.sh | sh
```

The installer picks a method on its own: Docker, then Podman, then Snap, then WSL, then a native
binary under systemd. To choose yourself, see [Choosing a Method](/get-started/install).

<Callout variant="warning">
Snap does not pair yet. On a host where it picks Snap, the command stops with `TENANT_ID is
required` before any code appears. Choose another method there:

```bash
$ curl -sSf https://cloud.shellhub.io/install.sh | INSTALL_METHOD=standalone sh
```
</Callout>

### Pair it

Given no credentials, the installer runs `shellhub-agent login`, which asks the server for a code,
prints it, and waits:

```
To accept this device, open the ShellHub console and enter this code:

      4KQP-7M2X

Enter it at https://cloud.shellhub.io/accept-device, or open the link:

  https://cloud.shellhub.io/accept-device?code=4KQP7M2X

Waiting for acceptance... (code expires in 10 minutes)
```

Where `xdg-open` is available, it also opens the link in the browser for you.

1. Type the code into the **Pairing code** field, or paste the whole link, and continue.
2. Check the device it found against the machine you are expecting: hostname, operating system,
   MAC address, agent version and the code itself.
3. Click **Pair into** your namespace. If it is not your machine, click **Not this one**.

Opening the link instead shows a page of its own with the code, hostname, operating system and MAC
address. Pick the namespace there and click **Accept device**:

<Shot id="accept-device" route="/accept-device?code=:paircode" of={{ testId: "auth-card" }} frame="band" edition="enterprise" viewport={{ width: 1440, height: 1200 }} alt="The accept page for a paired device, showing what it reported about itself and the namespace it will join" />

The agent stops waiting, joins the namespace and connects. There is no second command to run.

<Callout variant="info">
The code lives ten minutes. If it expires, run `shellhub-agent login` on the device, with `sudo`
on a native install, for a new one.
</Callout>

## Open a shell in the browser

1. Click **Open terminal** in the last step of the page. If you have left the page since, open
   the device from **Devices** and click **Connect**.
2. Check the login. It starts as `root`, and you can type any other.
3. Click **Open in browser**.

<Shot id="device-connect" route="/devices" of={{ role: "dialog" }} before={[{ click: { role: "button", name: "Connect" } }]} alt="The Connect panel for a device, with the login, the identity it connects as, the link to an external terminal and the button that opens the shell in the browser" />

The first time, the console asks to register the browser. It generates an SSH key that never
leaves the browser and adds it to your **SSH Identities** under the name you give it. After that,
the browser connects without asking, and you can revoke the key there whenever you like.

Nothing else had to be set up. Your namespace starts with one **access policy**, *Owner access*,
which lets you in as any login on every device.

## Open it in your own terminal

The same panel has **Open in external terminal**. It is an `ssh://` link, so your system hands it
to the SSH client it has registered for that kind of link. The command behind it is the device's
SSHID, which you can also run by hand:

```bash
$ ssh <login>@<namespace>.<device>@cloud.shellhub.io
```

The namespace and the device are part of the hostname, so an ordinary client reaches the right
machine through the one server that is listening.

The first connection with a key stops rather than opening. The server has never seen the key and
has no signed-in session to tell it whose key it is, so it prints a link and waits:

```
  ShellHub doesn't know this SSH key yet.

  Open the link to add it to your identities:

    https://cloud.shellhub.io/ssh-identities/new/2HP6S9DZ

  Security code:  2HP6 S9DZ
  Key:            SHA256:vXV24Lb0Uiy6jRbJ2ns7uFAgrfzS6qT1KPvu6MwKqCQ

  The console gives you a confirmation code once you add it.

Confirmation code:
```

1. Open the link in the browser you are signed in to, open **Login details**, check that its code
   matches the security code in your terminal, and click **Add key**.
2. Type the confirmation code the console shows at the `Confirmation code:` prompt.

<Shot id="login-approval" route="/ssh-identities/new/:approval" of={{ role: "dialog" }} alt="The approval screen for a key the namespace has not seen, showing the key, the account it would be added to and the namespace" />

The shell opens, and the key is now one of your SSH identities. Every later connection with it
goes straight through with stock OpenSSH. The link lasts 90 seconds. If it runs out, connect again
for a new one.

<Callout variant="info">
For anything unattended, add the key before its first run rather than after. Nobody is watching a
console to approve a pipeline at 3am. See [SSH Identities](/manage/access-control/ssh-identities).
</Callout>

## Where to go next

- **More devices**: open **Devices** → **Add Device** for the install command, and use
  [Provisioning Keys](/manage/devices/provisioning-keys) to enroll many without pairing each one.
- **Your team**: [invite members](/manage/team) and grant them devices with
  [Access Policies](/manage/access-control/access-policies). A new member reaches nothing until a
  policy says so.
- **More than a shell**: [File Transfer](/connect/file-transfer) and
  [Port Forwarding](/connect/port-forwarding)
- **Automation**: [API keys](/api#creating-a-key) and [their SSH access](/api/ssh-access)
